# TIA editor semantics and compatibility contract

2026-10-11. Proposed RungProof offline-language behavior, not a claim of Siemens CPU equivalence. Companion to tia-editor-upgrade-design.md. This specifies the requested end state; none of these new semantics are implemented or accepted by this document.

## Source baseline

`src/VirtualController/LadderProgram.cs` currently has target-only LadderCall, declaration-only interfaces, recursive LadderNode, and one terminal action per network. `LadderEditorDocument.cs` has flat editable paths and ExpandPaths distributes nested expressions into paths. `LadderEditorProjectJson.cs` supports editor schema 1; `LadderCompiler.cs` requires runtime schema 1. `WorkspaceProjectBundleRepository.cs` embeds ladder JSON in bundle version 1; WorkspaceRepository accepts workspace versions 1–9. Keep these formats independently versioned.

## CALL contract

The editor visibly distinguishes Legacy shared globals and Parameterized block semantics. Imported target-only calls remain Legacy even if their target has interface metadata. New parameterized blocks cannot be reached by legacy calls, and parameterized calls cannot target legacy blocks. Explicit block conversion is a validated, undoable operation; unresolved references become diagnostics, never implicit global bindings.

| Concern | Required offline behavior and acceptance |
|---|---|
| Targets | Parameterized CALL targets FC or FB only. OB is task entry only; DB is storage, not callable. Missing/deleted target diagnoses the exact call target field. Existing legacy rules remain for migrated legacy programs. |
| Scope | References encode global versus formal/local versus FB instance storage, not an ambiguous bare string. Local/global duplicate display names are allowed only with unambiguous qualified selection. Renames preserve symbol identity. |
| Formal types | Input/Output/InOut: BOOL, INT, DINT, REAL, STRING up to 255 characters, or ENUM with identical member domain. Exact types required; conversion is explicit. Timer/Counter and aggregate formals rejected with a type-specific diagnostic in this defined subset. Global aggregate leaf actuals of a supported scalar type are allowed. |
| Directions | FC: Input, Output, InOut, Temp. FB additionally Static. Static in FC is rejected. Temp supports scalar types above. FB Static supports those scalars plus TIMER/COUNTER; aggregate Static is rejected until a separately specified implementation. Input is read-only; Output is readable/writable local storage; InOut writable alias. |
| Binding completeness | Exactly one binding for each Input, Output, InOut; no duplicates/unknown names. Input accepts compatible literal or readable symbol. Output/InOut require writable storage, not literals or input-role globals. Unconnected output requires explicit Discard; InOut cannot be discarded. Missing input never silently uses a default. |
| Entry | Sample Input actuals once, in formal declaration order, before block instructions execute. Initialize FC Output and Temp from validated declared initial values on every invocation. Initialize FB Output and Static once on load/reset; retain on later invocations. FB Temp is initialized every invocation. InOut references resolve once at entry. |
| Transfer | Input reads use captured local values. Output writes update local output storage; copy out in declaration order only on normal fallthrough or RETURN. Explicit RETURN is normal completion. InOut writes take effect immediately at the referenced location, using the same destination validation/force rules as global writes. |
| Aliasing | Compiler rejects statically known overlap between any writable Output/InOut actuals in one call, including aggregate-leaf identity aliases. Resolve forwarded InOut references to their ultimate storage identity at entry and reject any newly discovered writable overlap before frame creation or effects. Input plus Output alias is allowed and means sampled old input followed by copy-out. Nested forwarding of a single InOut is allowed; overlapping writable actuals within the nested call are rejected. |
| Aborted/disabled | False enable does not create a frame or modify actuals/FB storage. Watchdog or execution abort suppresses Output copy-out, unwinds frames, and labels the invocation aborted. Already executed global/InOut writes and FB Static/Output writes are not rolled back; partial FB Output storage survives and is the starting value on the next call until overwritten or Reset. That retained internal value is not reported as a successful actual copy-out. FC Output/Temp frames are discarded. Recoverable arithmetic faults follow the instruction fault policy and do not by themselves invent a call abort. |
| Instances | Every FB call requires explicit instance identity bound to one FB type. Distinct identities have distinct Output/Static/timer/counter/edge state. Sequential calls of the same instance intentionally share state. A nested invocation of an already active instance is rejected. Instance identity/path is visible in monitoring. No implicit new instance per scan or per click. |
| FC instruction memory | Edge memory inside FC is keyed by owning FB instance ancestry plus static call-site path plus node ID, persists across scans, and clears on Stop/reset/load; Temp initialization does not erase edge memory each invocation. First evaluation after clearing establishes baseline without a pulse. TIMER/COUNTER locals in FC are excluded; explicit global instances remain available. This is an explicit offline policy, not vendor parity. |
| FB instruction memory | Edge memory is keyed by instance plus node ID. Static timers/counters use qualified instance storage. Nested instances use explicit project identities in this subset; no multi-instance declaration UI is exposed. |
| Recursion and tasks | Recursive call graph rejected, maximum call depth 32. Runtime retains defensive depth/active-instance checks. Tasks execute serially in existing deterministic scheduler order. Cross-task instance sharing is allowed only serially and observations identify each task. No claim of preemptive CPU task semantics. |
| Lifecycle | Stop clears all edge memory; first subsequent evaluation establishes baseline without pulse, matching existing runtime. FB scalar Output/Static and counters retain values on Stop; global output-role values follow existing Stop clearing. Instance nonretentive timers reset ET/Q/input/timing on Stop, retentive timers preserve ET/Q and clear input/timing, matching existing global timer Stop behavior. Reset and successful program load reinitialize all instance storage/edge memory and increment execution generation. Save/reopen stores declarations and initial values, not a live-state checkpoint. No power-cycle retentivity claim. |
| Failure diagnostics | Invalid calls remain editable and saveable; Verify + Load rejects them without replacing the running program. Error points to target, instance, or specific binding. No fallback to shared globals. |

Required tests: independent FB instances; same-instance sequential calls; nested distinct-instance calls; nested active-instance rejection; FC Temp and Output initialization; FB Static and Output retention; Input sampling with overlapping input/output; duplicate writable aliases; aggregate leaf actuals; skipped calls; RETURN and aborted call copy-out; force interaction; two serial tasks; reset/reload; missing/extra/wrong-type actuals; depth boundary 32/33; legacy metadata remaining inert. Tests must assert effects, not only labels or compilation.

Timer time accounting: legacy global timer behavior remains unchanged by migration (current runtime advances by ScanPeriod on each applicable evaluation). New FB Static timers advance by at most one ScanPeriod per controller scan per instance timer; the first applicable Advance consumes that scan's time quantum, subsequent invocations get zero additional time but still process input/reset/Q transitions in order. A reset within that scan does not grant another quantum. A skipped scan contributes no time retroactively. Separate instances each receive their own quantum. This explicit discrete offline policy avoids double elapsed time from repeated FB calls; help and observation details identify legacy versus instance policy. Tests cover true/true, true/false/true, reset/true, two tasks, periodic skip, and all timer kinds. This policy is not presented as real CPU wall-clock behavior.

FC edge-memory task scope: the same static FC call path outside an FB shares its edge memory when reached by two serial tasks. Task ID is observation provenance, not a separate storage identity. Within an FB the owning instance ancestry separates the state. Add a two-task regression proving this explicit policy; do not infer separate storage from the monitoring context selector.

## Recursive editable network contract

Editable network consists of a stable network ID, a recursive expression root, and at most one terminal action. Expression leaves are Contact or Compare; Series and Parallel contain ordered child nodes. No terminal action inside an expression branch and no arbitrary graph/cross-wire links. A network with no action is an editable draft and fails Verify + Load. Output chains and branch-local outputs are outside this defined language; never show insertion affordances suggesting they work.

Terminal action includes every existing LadderNetwork action: coil, timer, timer reset, counter, counter reset/load, numeric/text operation, CALL, RETURN, JMP and LABEL. LABEL remains a structural marker regardless of continuity; RETURN/JMP retain their existing conditional control flow and block-local label resolution. Network/expression/action IDs are unique across the program, not just within a block; symbol/block/task/instance identities have explicit namespaces. Imports and paste check the complete program's identity set.

Series evaluates children left-to-right, Parallel top-to-bottom; preserve current runtime evaluation of every child, including when continuity is already false/true. No Boolean-algebra distribution, flattening, short-circuit optimization or duplicated leaf evaluation. Empty Series is an explicit wire (TRUE); empty Parallel is FALSE. Preserve imported empty shapes exactly and label them; the authoring command creates Parallel with two Series paths, not an implicit empty Parallel. Removing a last required root creates an explicit empty Series; removing a path removes exactly that subtree. Network deletion deletes the entire explicitly selected network.

Branch commands select exact subtree boundaries. Insert before/after wraps or inserts in Series as needed; add parallel path wraps the selected subtree plus a new empty Series without cloning it. Moving/replacing nodes preserves unaffected IDs; duplicate/paste allocates fresh IDs recursively, including the terminal action. The same measured tree layout drives drawing, wire-slot hit-testing, keyboard traversal and selection reveal. Unsupported imported graph shapes produce a readable diagnostic, not a flattened approximation.

Required fixtures: flat legacy rung; nested Series(Parallel(...),edge); nested empty Series/Parallel; deep branch at supported depth; duplicate IDs; missing/extra action; unsupported graph; copy/paste subtree; undo/redo; renderer switching. Assert node identities, visit counts/order and runtime values before/after save/reopen, not only Boolean truth tables. Supported editor depth is 32; deeper imported trees are rejected with path/depth explanation without changing the source file.

## Versioned persistence contract

| Format | Read/write policy |
|---|---|
| Editor project | Read v1 and new v2; write v2 only after successful migration. v2 carries recursive tree, explicit call/block semantic mode, stable symbol/instance identity and bindings. Existing v1 interface metadata is retained as metadata in Legacy mode. |
| Runtime program | Read v1 and new v2; v1 normalizes to explicit Legacy representation, preserving execution. New typed calls require v2. Existing recursive v1 trees import structurally, without ExpandPaths distribution. Unsupported shape is rejected with exact path. |
| Integrated bundle | Keep outer bundle v1, whose embedded ladder JSON has its own version. Read embedded editor v1/v2 using the same loader. Preserve workspace version 1–9 and all workspace data; this editor change does not migrate scene/workspace schema. |
| Unknown versions | Refuse editing/load with a version-specific message; no downgrade/save-back. Original bytes stay untouched. A readable JSON parse alone does not mean migration succeeded. |

Migration occurs in memory first and never overwrites during Open. First save of a migrated file creates a non-overwriting sibling backup of the original and uses validated temporary write plus atomic replacement; backup or validation failure aborts replacement. Save As leaves original intact. Migration does not generate default actuals from old declaration names or initial values. If stable IDs need repair, reject duplicates instead of silently remapping references. Old generated root IDs become persisted v2 IDs; unaffected leaf/action/block/task IDs survive.

Fixture suite must preserve project identity, names, invalid drafts, tag types/initials/bindings, enum/aggregate schemas, all block/task/interface fields, active block, watch selections, scene ID, workspace placements/groups/connectors/signal links/template and finite-belt/roller/drive relations, plus diagnostic/reference target identity. Include all five existing demo projects, an invalid draft, an integrated workspace bundle, nested runtime program and future-version files. Byte-preserve originals on every failure. Compile and compare legacy scan outputs/events before and after migration across a fixed input sequence.

## Edit transactions and navigation

All multi-field properties, inline operands, tag/interface/block/task forms stage draft edits. Typing and dropdown changes do not mutate the document. Apply/Enter validates the complete operation and commits one history item; Escape/Cancel discards all staged edits. Focus loss keeps the draft visibly pending and does not commit. Switching target/block with a pending form offers Apply/Discard/Cancel navigation. Invalid data keeps the draft, marks the failing field and makes no partial mutation. An undefined-tag create-and-assign flow stages both and commits one atomic transaction; cancelling creates no tag. Save refuses to silently ignore a pending form: Apply/Discard/Cancel first.

History is for document mutations; selection/navigation and monitor/force actions are not project undo entries. Force actions affect the offline session explicitly and are separately logged. Undo/redo invalidates open edit/context targets and re-resolves selection by stable ID. A context command stores document revision, block and target ID/path; revision change, deleted node, block switch, undo/redo, or mutation lock causes a harmless rejection with a reason. No fallback to current or final contact.

Navigation commands reveal their parent dock, select the tab, scroll and focus the exact target. Diagnostics carry stable instruction ID plus operand role in addition to source path; if the draft changed, show stale diagnostic and revalidate instead of selecting a different instruction. Aggregate watches navigate to the root declaration and selected member. Blank/duplicate/invalid form entries show an inline diagnostic and leave state/history unchanged. Copy on output means output-only clipboard; Copy network remains a distinct command. Cut is atomic copy-and-delete only where deletion leaves a supported editable draft.

## Native acceptance dimensions

Qualification viewports: 1280x720 and 1600x900 logical pixels; Windows DPI 100%, 150%, 200%; ladder zoom 75%, 100%, 150%. Test both styles at every combination using compact/dense/long-name fixtures; require accessible scroll/pan rather than fitting every rung on screen. Menus remain within work area; inline editors, numeric sign/decimal/unit, and selection are readable with no ambiguous clipped values. Full details are reachable for deliberate ellipsis.

Real pointer/keyboard workflow includes right-click wire/operand/header, Shift+F10, F2 inline edit, Enter/Escape, menu-edge positioning, drag/drop, text-field shortcut isolation, hidden-dock reopen and saved/reopened nested/CALL projects. Record input-enabled native checks separately from no-focus rendered captures and synthetic routing tests. Final exported binary/source fingerprint, test logs and captures must refer to the same candidate; no source-only pass qualifies the desktop build.
