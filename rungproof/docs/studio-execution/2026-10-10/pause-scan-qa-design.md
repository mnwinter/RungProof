# Pause, one accepted scan and read-only history: QA design

Disposition: DESIGN ONLY. Read-only source review plus this document; no runtime/source implementation, build, engine run or new qualification. Existing E504 demo/mapping evidence remains unchanged. This proposal uses the five existing demos and the two already bounded finite workspaces, not additional presets or all77 acceptance.

## Source facts that constrain the design

- `VirtualControllerSession.cs`: one accepted scan samples BOOL/numeric/text, executes PLC, commits outputs, advances plant by exactly ScanPeriod, clears consumed pulses, then emits ScanCompleted. Advance has a fractional/backlogged accumulator and a 1000-scan batch bound. Stop discards unscanned pulses/backlog; Reset clears inputs/program memory/forces.
- `VirtualControllerRuntime.cs`: current state enum has only Stopped and Running. Stop clears output images, edge state and nonretentive timers; it cannot implement state-preserving Pause.
- `Main.cs`: ordinary physics calls session.Advance; current-draft Run validates and loads changed logic without resetting actual plant. Valid project Open intentionally uses resetScene:true. Invalid Run stops the prior execution. These distinct paths must remain distinct.
- `SceneSimulationRuntime.cs`: SetControllerPlaybackRunning(false) is also not state-preserving Pause. It invokes PausePalletizerClock (discards pending Start) and StopWorkspaceRollerPreset (speed zero). RefreshEquipmentClock enables generic controllers when playback runs; gating only session.Advance would leave autonomous functional equipment able to move.
- `VirtualControllerScanCompleted.cs`: accepted sampled/effective/output primitive images are copied; event identity is scan/time. This is the authoritative existing hook for read-only history, not SnapshotPublished, which also fires on Run/forces/Stop/Reset without a scan.
- `Main.ApplyVirtualForce`: an explicit force immediately projects its snapshot through the existing bridge. A deliberate force can change current command image while paused, but must accept no scan/time/plant motion. Do not falsely describe that edit as a new accepted scan.

## Proposed contract to freeze before implementation

All API names below are proposals, not existing callable methods. A general Pause must have an explicit visible state while retaining PLC memory, output images, speed, phase, load pose, queued momentary inputs and accumulator. It must suspend both accepted scan advancement and autonomous functional animation without calling current Stop-like helpers. Decorative ambience is outside the plant proof and should not obscure whether equipment is stationary.

Normal elapsed calls while paused accept zero scans and accrue zero wall time. Preserve the pre-pause fractional/backlogged accumulator. An explicit one-scan action accepts exactly one ScanPeriod through the same sample/execute/commit/plant/pulse/event route, remains paused afterward, and does not drain or add to the ordinary accumulator. Resume retains that pre-pause accumulator; paused wall time is never replayed. Example: running 0.015s of a 20ms scan, Pause, wait 5s, Step once, Resume then 0.005s yields one stepped scan plus one resumed scan, not 250 catch-up scans.

Step is available only for the built-in controller with a valid, current loaded program and supported active plant. It must not silently resume wall-clock running. Empty/invalid current drafts, draft/loaded mismatch, external mode, or an incompatible active challenge must disable Step with a specific reason. Recommended first scope excludes isolated challenge Test mode and external PLC mode rather than inventing step semantics for either. Run remains the explicit changed-draft load action; a changed valid draft must never Step the stale loaded program.

Mounted/operator actions while paused may queue the same declared momentary input or change a maintained operator input; they must not execute PLC logic, move equipment or synthesize feedback. Explicit force edits retain their existing force ownership and invalidate observed trials; Step uses the effective accepted image. Paused BOOL force display and current command may differ from the last accepted row, so the UI must label both.

Stop remains command-clearing, speed-zero for the finite roller, pending-pulse/backlog discarding and historical-outcome retaining. Reset clears forces, accepted clock and history epoch, restores exact native homes and measured beam, and stops. Pause must not mark an observed trial Incomplete or change its accepted-time timeout; Step feeds the existing observer once. Stop/Reset/scene/load/draft/layout boundaries keep their existing retirement policies.

## Immutable bounded history sample contract

Root ratified a fixed-capacity ring of128 accepted rows per controller/layout/reset epoch, superseding QA's initial256 proposal. Show an explicit dropped-row count and first/last retained scan IDs. Memory is bounded by row count and declared signal size; large aggregate values must not be silently retained as live mutable objects. No per-scan scene node/resource references are allowed.

Each accepted row contains:

1. Controller token, scene/runtime type, program execution identity (watch-only metadata excluded), layout identity, reset epoch, scan number, accepted simulated time and period.
2. Copied sampled BOOL/numeric/text input image and copied effective image. Label sampled as pre-force PLC sample, not necessarily raw hardware: session operator overrides are already applied before ScanCompleted's sampled image.
3. Copied accepted BOOL/numeric/text output image, active forces and copied diagnostics. Force edits between accepted scans are current-state events, not fabricated accepted rows.
4. Typed post-plant scalar observation for each supported fixture: generated feedback and relevant phase/position/speed/count. Finite roller includes Center/SpeedMps/DriveSurfaceTravelM/ClampedLoadTravelM/BeamBlocked/AtTerminal/HomeCenter/TerminalCenter. Belt uses its existing snapshot. Demo5 distinguishes commanded cycle/vacuum from actual attachment/home/placed/fault.
5. Truthful absence of per-element evaluation where unavailable; no inferred energized/false status. Device-to-rung references use the same accepted loaded/current identity. A historical row cannot navigate against changed source as though it were current.

Physical transform arrays and complete accepted payloads belong in QA evidence for equivalence; UI ring need not retain31 transform strings every scan. Do not serialize the scene graph into the user-facing history.

Pure history tests must mutate original input dictionaries after append, attempt mutation through every exposed dictionary/array/list, retain old rows through ring wrap and check exact bounds/order/drop count. Stored rows and runtime must remain unchanged. Reading/selecting/exporting a retained row accepts zero scans and causes zero output/plant writes. No record is created by mere render/monitor refresh, Run, Pause, force mutation, blocked Step, Stop or Reset.
