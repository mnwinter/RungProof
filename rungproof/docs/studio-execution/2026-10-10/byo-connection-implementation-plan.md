# One generic belt command/feedback connection — implementation plan

2026-10-11. Design only. This follows `byo-connection-department-audit.md`; no product writes, build or engine run. Existing typed lessons are the coordinating studio's next qualification priority. No new menu preset, material transport graph, campaign evaluator, or external PLC connection is selected here.

## Bounded contract

One learner-added existing asset `material-handling.belt-conveyor.600x6000.v1` in existing offline source `scene-1-conveyor-stop`. Its authored conveyor, carton and photoeye remain under their existing owner; this added belt has no load. Require unit scale and zero rotation for the first runtime-supported connection; other saved layouts remain authored-only unless explicitly supported later. No physical connector is necessary for drive feedback. Optional existing visual links keep their authored-only meaning.

Exact catalog signals: `run_command` BOOL input, `running` BOOL output, `actual_speed` float32 output unit `m/s`. Bound runtime points, proposed per-instance names:

| Point suffix | Type / owner / role | Asset endpoint and meaning |
|---|---|---|
| `_run` | BOOL / PLC / output | `run_command`: actual effective learner output |
| `_running` | BOOL / PC / input | `running`: existing `abs(ActualSpeedMps)>.01`, including coast |
| `_actual_speed_mps` | REAL / PC / input, unit `m/s` | `actual_speed`: measured controller speed, not run command |

Keep speed `.65 m/s`, acceleration `.75 m/s²` and simulator permissive true, using current `ConveyorController` defaults. No new speed/permissive mappings in this contract. Reject conflicting generic maps for this opted-in instance. Existing autonomous generic assets and qualified finite presets retain their current behavior. No feedback is invented for unsupported asset outputs.

Names and prospective APIs below are proposals. They do not exist merely because this document names them.

## Verified seams and real prerequisites

`WorkspaceSignalRuntimeAdapter.AttachSupportedController` already attaches `WorkspaceRuntimeAdapter`. `ConveyorController` exposes `RunCommand`, `EstopOk`, `SpeedSetpointMps`, `AccelerationMps2`, `Running`, `ActualSpeedMps`, `ApplyPlantTravel(distance,speed)` and `ResetPlantTravel()`. Its `_PhysicsProcess` currently integrates speed and travel every physics frame. Therefore routing output getters alone would give frame-timed feedback, not accepted-scan causal feedback.

`Main._PhysicsProcess` and `StepActiveController` pass `_sceneRuntime.AdvanceSimulation` into the same `VirtualControllerSession` accepted cycle. Typed commits happen before this plant callback; `CaptureScanInspectionPlantInputs` copies declared PC points afterward. `SceneSimulationRuntime.StateChanged` invokes `ApplyWorkspaceSignalMappings`; this event can occur repeatedly during commits/plant binding updates. It must not become an integration clock.

`SceneSimulationRuntime.Points` is read-only; owner/type dictionaries are private. `IsPcOwnedPoint` and `IsPlcOwnedPoint` are public predicates. `SampleVirtualControllerInputs/NumericInputs/TextInputs` return declared PC values. `CommitVirtualControllerOutputs/NumericOutputs/TextOutputs` explicitly accept PLC owners only. There is **no** generic PC feedback publication API; never route feedback through a PLC commit method or mutate an exposed dictionary.

`WorkspaceDocument` stores placements, visual connector links and signal links, not additional scene-point declarations or unit constraints. `WorkspaceRepository.ValidateConnections` compares primitive signal/point type only. `SceneIoPoint` carries type/owner/role/purpose but no unit; `SceneIoBindingValidator` already rejects duplicate declarations, absent binding, wrong owner/type and competing PLC writers. `SimulatorShell.TryBuildCurrentLadderProgram` validates against its scene points. Declaring new tags only in the editor cannot create scene I/O.

`WorkspaceProjectBundleRepository.Validate` validates the workspace and readable ladder source identity; compiler-invalid but readable ladder JSON is intentionally preserved. `Main` workspace restore rebuilds the runtime; any augmentation must feed the same effective scene definition to composition, runtime, shell I/O declarations and validation, before a controller can load.

## Implementation sequence

1. **Pure contract and persisted shape.** Add a narrowly named optional drive-connection relation to generic workspace documents, with explicit instance ID, contract version and the three point names. This is a connection relation, not a preset or automatic scene factory. Proposed schema version9 must extend repository version checks without weakening version7/8 preset validation. Derive the three declarations from the relation rather than accepting arbitrary owner/type strings. Validate exact asset/signals/source, names, units, reserved-name collision, supported pose and at most one opted-in belt. Existing documents remain readable. Match generic interactive and saved-load validation.
2. **Single effective scene contract.** Create a pure augmentation function that copies the existing simulation JSON and appends only these declarations. Preserve all original points/actions/bindings/scene identity and external profile exclusion. Feed this derived definition to `Main` composition/runtime and `SimulatorShell`. Keep the saved original scene fingerprint or equivalent revision check so an incompatible source does not silently rebind. Do not persist a wholesale arbitrary simulation JSON override. Make the effective declarations visible in actual tag-binding selectors, monitors and saved joint project validation.
3. **Accepted projection opt-in.** Refactor the existing conveyor ramp integration into one shared method without changing the ordinary autonomous algorithm. Add an explicit controller opt-in disabling its physics callback, then call that shared integration once per accepted period. Retain its current end-speed-times-period travel rule for this slice; do not imply analytic integration. `ApplyPlantTravel` already projects actual drums and duplicated UV materials. Capture its authored homes and keep finite belt's prescribed-travel use unchanged. Opt-in/replacement/reset must not leave two clocks or an autonomous callback re-enabled.
4. **Validated PC feedback writer.** Add one runtime-owned method which accepts only the registered connection's PC BOOL/REAL declarations and finite numeric values; reject unrelated points and PLC owners. Build all measured values first, publish as one coherent post-plant image, then notify state change. Ownership remains tied to exact runtime/placement identity. It writes `Running` and `ActualSpeedMps` from the real controller after integration; no command proxy and no sensor claim.
5. **One accepted plant callback.** Introduce one Main wrapper shared by ordinary `Advance` and paused `StepOneAcceptedScan`: advance existing scene plant, validate live connection lifetime, apply the effective mapped run image, integrate the opted-in belt once, publish its PC image. Use the existing post-plant capture afterward. Do not integrate from `StateChanged`, `ScanCompleted`, history publication or a second worker. Apply routing/UI refreshes may reassign commands but cannot advance motion. Avoid the generic clear/reapply lifecycle accidentally re-owning this connection; give the opted-in relation its own validated routing branch and retain old autonomous mapping regression unchanged.
6. **Lifecycle and UI.** Explicit command/feedback connection creation must be a user editing action using current generic workspace paths, not a new preset selector or solution loader. Expose LIVE INPUT / LIVE FEEDBACK only after actual adapter eligibility. Declared points and feedback availability must be visible; missing link/output is unavailable, never a counterfeit measured zero. Bound relation identity joins current program identity for Run/Step gating and history epoch retirement.

## Clock and lifecycle details

Scan N sample contains the previous measured speed; forces produce a distinct effective image. Current draft execution owns run. Its effective output is committed; one existing scene plant period and one opted-in belt period advance; copied post-plant feedback is recorded. Scan N+1 samples this new feedback. The normal accepted cadence is whichever valid project period is loaded: verify20/40/100ms. A large wall-time advance may accept multiple cycles under the session's existing bounded backlog policy; no independent belt integration is allowed between them.

Pause is explicitly enabled for this connection only after its accepted-clock contract passes, rather than treating every BYO placement as supported. Wall time preserves command, speed, all drums/UV and pending inputs. Step accepts exactly one cycle while staying paused. Resume validates current program plus connection identity. Force changes retain existing paused rejection; a running command force must affect actual motion and invalidate observational claims without rewriting older rows.

Command-map detach while running clears only the acquired run ownership; later accepted scans decelerate normally and measured running stays true until threshold only while feedback relation and current compiled identity remain valid. Detaching a feedback map marks it unavailable, retires the program/history binding epoch and Stops/freezes accepted execution: no accepted coast follows retirement. Rebind regenerates declarations and validates the current draft before Run. Rebind/Undo uses current physical measurement, not a historical cached value. Other remaining generic mappings continue normally.

Stop is distinct from command OFF: for the opted-in accepted belt, immediately zero speed, hold drums/UV and clear pending scan time; Reset restores exact captured homes/UV, force-free scan zero, false run/running and speed0. Program changes preserve physical pose under existing `resetScene:false` semantics; actual project Open starts fresh stopped/home. Invalid current Run stops; invalid paused Step is blocked with state/pose unchanged. Graph edits, placement replacement and connection removal retire clocks/leases and declare unavailable atomically before the next accepted scan. Named scene actions remain guarded; no direct command/feedback mutation while paused.

Save/Undo/history retain exact relation, mappings, added declarations, current valid/wrong/invalid ladder JSON, path/baseline/dirty state. Reopened projects do not restore transient speed/phase as simulated history. Failed open restores the previous project atomically, including draft cache and undo history. Refuse external/challenge mode; no PLC profile/transport creation. Existing Pause/history remains ring128 immutable; selection cannot invoke routing or motion.

## Acceptance and sequencing

Pure tests must exercise version compatibility, exact instance/asset/endpoint eligibility, missing controller metadata, pose limits, collision with authored point names, incorrect owner/type/unit, duplicate writers/input targets, conflicting generic maps, endpoint pair duplicates UI/load parity, malformed relation and atomic saved roundtrip. Run the existing finite relation/typed I/O tests unchanged. IO validator ownership is necessary but unit/runtime-adapter checks remain the new connection policy's responsibility.

Native tests must use actual asset nodes, disk-open joint projects and current editor Run at20/40/100ms. Intended program runs for a bounded timer then removes command; verify applied output, exact existing discrete ramp, actual drums/UV, measured PC speed/running, legitimate positive-speed coast with runFALSE, later zero, and N→N+1 sample causality. Compile-valid wrong program retains run after the threshold; verify positive speed and continued phase/UV without corrective writes. Invalid current code blocks stale execution midmotion and survives exact joint reopen. Forced run/effective image, missing/replaced node, detach/Undo/redo/rebind, Stop/Reset, pause wall time and oneStep all need real native checks.

History/observer disabled versus enabled must yield identical full accepted payloads, measured points and every actual transform/UV. Verify actual UI owner/unit choices, authored-only visual connector status, live feedback and unavailable detach state on the exact final binary. Existing generic detach fixture uses injected declared outputs; keep it as a separate regression, not substitute for learner acceptance. No beam or transported object is part of acceptance.

Technical blockers are implementation prerequisites, not permission holds: persisted derived point contract, merged shell/runtime declarations, validated PC publication, exclusive accepted projection, current binding identity and unavailable-feedback gating do not currently exist. Root can schedule them after the three typed lessons; this plan does not implement them.
