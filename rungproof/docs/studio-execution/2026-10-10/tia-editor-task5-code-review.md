## Findings

1. **P1 — Aborted execution still enters successful-scan consumers.** `src/VirtualController/VirtualControllerSession.cs:266` invokes `ScanCompleted` unconditionally after checking completion only for the counter/return value. Watchdog partial scans therefore reach consumers such as `src/App/Main.ChallengeLabels.cs:163` and the event-count gate at `src/Challenges/ChallengeTestRunner.cs:99` under the successful-event name. Preserve existing watchdog output commits and plant advance, but publish a separate attempt event and invoke `ScanCompleted` only for Completed. Retain completed and aborted attempt envelopes in history. Add an event-count regression with one watchdog attempt: attempt event=1, completed event=0, commits/plant=1, history=1. Root's proposed success-only ScanCompleted plus ScanAttempted ruling is consistent with contract section 4 and the implementation plan's explicit successful-consumer requirement. ScanAttempted should carry explicit disposition; naming must not imply it fires only before execution.

2. **P1 — Interrupted attempts disappear rather than receiving an original-identity disposition.** `VirtualControllerSession.cs:210,223,225,227,231,237` return false after a lifecycle-changing callback; catch at `272` also suppresses failure when generation changed. Reset correctly remains the current publication, but the executed instruction observations and any completed commit phases vanish. Contract section 4 explicitly requires the interrupted result to be abandoned/aborted under its original identity. Emit/store an independent original-origin attempt envelope without replacing the newer lifecycle publication. Capture immutable execution identity and images before callbacks, and record completed phases before testing invalidation. Extend ResetRejectsLatePublication to assert an abandoned old-generation result while the active publication remains Reset, including variants changing lifecycle during input sample, numeric commit, plant advance, and post-plant sample.

3. **P2 — Failure publications lose captured image evidence and mislabel program failures.** `VirtualControllerSession.cs:202,214,275–280`: phase remains InputSample during `_runtime.Scan`; failure construction initializes none of SampledInputs, EffectiveInputs, ProgramEndValues, PublishedValues or PostPlantInputs. A plant callback failure with OutputsCommitted=true cannot expose the actual committed/consumed images through its envelope. Hoist phase images outside try, set Program before Scan and Publication before event callbacks, preserve available images, and explicitly explain unavailable images. Test each failure phase, including numeric/text commit after BOOL commit; do not imply atomic outputs merely because an earlier callback completed.

4. **P2 — Observed nodes do not carry upstream continuity.** `src/VirtualController/VirtualControllerRuntime.Observations.cs:80` records every contact/compare/container with NetworkEnable=null. Only the network/action records carry the final aggregate. In a series FALSE contact followed by a TRUE comparison, local result=true cannot describe the comparison's upstream FALSE flow, required separately by contract sections 5–6. Capture the existing traversal's incoming continuity while evaluating each child once; retain non-short-circuit evaluation. Parallel children inherit the branch's incoming continuity; series children receive the accumulated incoming continuity. The per-node enable must never be inferred from the final network result or reevaluated from final values. Add FALSE→TRUE series and mixed parallel fixtures proving consumed operands/local result remain available, upstream continuity differs, and monitoring on/off results/visit order agree. This is a contract gap, not evidence that current executor results changed.

5. **P2 — Watchdog result lacks required explicit abort progress metadata.** `VirtualControllerRuntime.cs:334–348,612–614` and `InstructionObservation.cs:107` retain IsPartial plus a general failure code, but no explicit executed-network count/last fully observed instruction fields. Trace/global-last may permit derivation only when monitoring is enabled and relevant IDs fit capacity; they do not guarantee the abort metadata independently of capture limits. Add a completed-network counter and last fully observed instruction identity/ordinal to the attempt result, avoiding the existing watchdog counter's 10001st rejected visit being called executed. Test monitoring disabled and capacity exceeded as well as a normal partial capture.
