## Minimal additive native test/capture proposal

One new QA partial, one root-owned flag/dispatch/capture seam, no product camera behavior change. Load exact EV/Chicken scenes through normal catalogue/scene flow, await layout/process frame and retain normal initial framing. Prepare EV unequal projection fixture/Chicken actual stable state with already qualified APIs and label those preparation scopes explicitly. Never call diagnostic SetCamera/LookAt/Fov/FocusOn/CaptureCurrentView to reach the readout during the navigation test.

1. Snapshot actual camera pose, ViewTarget, aperture and runtime/field identities. Push middle/right/wheel events outside aperture over actual left/right/HUD rectangles; assert unchanged camera/target. Push motion without captured button; assert unchanged. Ladder-hidden aperture must reject new pointer gestures.
2. Route middle press at aperture center, finite motion chunks, release through GetViewport().PushInput. Route right orbit similarly, then finite wheel-up presses. Await real ProcessFrame after each stage; all projection/text observations must use the resulting actual camera transform, not stale cache coordinates. Release outside and view-switch cancel tests retain existing gesture policy.
3. Read the known target label/housing world position only as a QA navigation oracle. Derive bounded pan motion from camera X/Y error and current controller distance/scale; use finite small chunks. This chooses events without setting camera target/pose. Orbit only via events to expose the actual front face, then pan before wheel zoom because zoom is not cursor-centric. Log every routed event and before/after camera/target/aperture. Cap event count/iterations and fail reachability honestly if no usable view is reached.
4. For EV, both passive BAY A/B PLCkWh identities and independent live values must fit unobstructed aperture simultaneously, with physical grouping intact. For Chicken, screen/MeasuredWeight and kg text must fit and face camera. Project actual configured label mesh/extent corners; require front-facing/non-behind, full bounds inside aperture with margin, meaningful pixel height and no HUD overlap. A six-vertex label quad is extent evidence, not per-glyph shape certification. Choose and document a baseline readability threshold (e.g.12px minimum text-line height) before acceptance, then visually inspect actual PNG at native1600×900.
5. Save screenshot only after routed sequence and real frame; dedicated sidecar must record normal starting camera, exact scene/DLL/engine/image hashes, complete event trace, final pose/target/aperture and projected label rectangles, preparation-fixture provenance and runtime unchanged-by-navigation assertions. Reuse nonfocus capture infrastructure; no global OS cursor/key control.

Projected bounds do not prove absence of geometry occlusion where imported scenery lacks colliders. Actual rendered inspection remains mandatory; avoid describing simple physics rays as complete visibility proof. Split/operator apertures should be tested where the UI normally permits navigation; a diagnostic crop cannot certify ordinary access. No automatic controller output/action should be introduced merely to make camera testing pass.

## Honest acceptance boundary

This would establish **scripted in-app InputEvent routing and sampled ordinary camera reachability**, including UI aperture handling, not physical keyboard/mouse ergonomics, discoverability or all77 hands-on acceptance. Real human/OS input, DPI variants and comfortable ordinary overview text remain separately unverified unless explicitly exercised. Finite EV+Chicken reachability closes only those two navigation evidence gaps; no unconditional154-frame replay or camera refactor is needed.
