## Purpose

The intended lesson is staggered startup of ten motors with group alarm handling. Each motor now accepts its own PLC-owned BOOL, `motor_0_run` through `motor_9_run`. A loaded controller can time these independently. The retained `motor_array_run` BOOL requests all ten motors together; keep it false during independent sequencing. The scene also declares motor_commands as a fixed BOOL ARRAY [0..9]. Load or author controller logic before Run; a separate typed QA controller is generated by the aggregate audit. Structured tag controls are implemented; native normal schema authoring and typed-project acceptance remain open.

Each `motor_N_run` binds to `motor_N`. Running bindings are combined with logical OR for this scene: a motor stops only when its typed motor_commands[N], legacy individual command and group command are all false. Aggregate-only sequencing must keep the legacy commands False. OR projection preserves the actual ARRAY values. Reset clears all command sets. Other scenes retain their existing binding behavior.

## Typed ARRAY boundary

Use constant-index operands such as motor_commands[0] through motor_commands[9]. Out-of-range indices, malformed shapes and BOOL/numeric mismatches are rejected. Dynamic indices, nested aggregates and whole-array instructions are unsupported. Backend and headless checks do not establish native readability, normal schema editing or physical motor behavior; current native typed-interface acceptance remains pending.

## Stop and safety boundary

A normal Stop removes PLC-owned commands according to the scene runtime. This document does not prove a safety function, a real E-stop circuit, a PLC watchdog, or live-machine commissioning.

## Machine guide

Current behavior supports individual and group command projection. To stagger startup, the controller must time `motor_0_run` through `motor_9_run` while keeping `motor_array_run=False`. The renderer does not generate delays or command outputs.

### Start conditions

- The common PLC/watchdog foundation is healthy.
- All required simulator inputs are at their documented initial state.

### Normal sequence

- Apply the requested input condition.
- Verify only the documented PLC outputs respond.

### Expected observations

- A loaded controller commanding `motor_array_run=True` animates all ten motors together; `False` stops their animations.
- Alarm handling depends on the authored controller removing its command when `group_alarm_clear` is false. The scene binding does not enforce that interlock itself.
- Individual commands animate their corresponding motors independently. A complete native timed-controller cycle is still pending verification. The supported status panels display the OR-combined command count and the startup_sequence_active command. They report commands, not measured motor feedback or timer state.
