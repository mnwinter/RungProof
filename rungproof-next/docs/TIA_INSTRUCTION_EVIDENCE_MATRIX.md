# TIA instruction evidence matrix

Updated 2026-10-15 from the current `LadderInstructionCatalog`,
`LadderInstructionPresentation`, Siemens STEP 7 V21 references, and the user
screenshots. This is a review ledger, not proof of parity. Every native Siemens
entry remains open until evidence is captured from the running editor for
matching TIA and RungProof states. Explicitly local RungProof operations are
`N/A` for TIA state gates once the UI segregates them and no Siemens parity
claim remains.

## State gates applied to each key

| State | Evidence required per instruction |
| --- | --- |
| Offline, unselected | Correct Siemens LAD symbol/box, dimensions, pin names/order, operand/instance placement, continuous rung conductors, and current operand/tag-information settings. |
| Offline, selected | Selection state matches the corresponding TIA object type; selection does not cover symbols, pins, conductors, labels, or values. |
| Operand edit | Correct editable fields and placeholders at the Siemens pins; missing operands remain missing and produce a visible diagnostic. |
| Online, true/false/unknown/unconnected | Live values align with their pins; conductor segments reflect evaluated power flow across the complete rung and each branch. Unknown/unexecuted remains distinct from false, and Siemens' black not-interconnected state remains distinct from both. If an instruction is not executed in the current scan but has an identity-matched earlier observation, retain only its value presentation at 50% color saturation; current power flow remains gray/unknown. Never carry a value across session, load, execution-generation, or program-content identity. RungProof's renderer has four separate style states. A valid loaded LABEL is the first explicit `NotInterconnected` topology: the marker is outside the destination network's power-flow conductor and stays black while that network remains independently green, blue-dashed, or gray. Other unconnected LAD outputs remain unmodeled. |
| Zoom/display settings | No overlap or clipping at normal and 100% zoom; verify symbolic, absolute, both, tag information hidden/shown/hierarchical, and both tag-information positions where applicable. Operand representation and supplementary tag information are independent. Never invent or leave a synthetic `instance.member` label/value beside an instruction pin when the selected TIA settings do not show it; hiding tag information must suppress those annotations but preserve actual operands, formal pin names, and the instance DB identity where TIA displays it. For every timer/counter output, keep Q and ET/CV values on their own pin rows, clear of each other and the right power rail; no clipping is acceptable at the editor's supported widths and zooms. Apply this check to every supported instruction family, not only timers/counters. |

## Cross-cutting monitored power-flow rule

For IEC timer and counter boxes, distinguish rung power entering the instruction
from its Boolean output: the incoming conductor colors from `NetworkEnable`,
while the conductor from the instruction to the right rail colors from the
observed `Q` value. Do not color the outgoing conductor from execution enable
when `Q` is false. The shared renderer helper applies this rule to TON, TOF,
TP, TONR, CTU, and CTD; focused controller tests exercise both Q states for all
six. Current-build running-editor captures `.tools/tia-ton-q-false-flow.png`,
`.tools/tia-ton-q-true-flow.png`, `.tools/tia-ctu-q-false-flow.png`, and
`.tools/tia-ctu-q-true-flow.png` were visually inspected. RungProof now shows
the input side green while a false Q keeps the output side blue-dashed, then
shows a true Q powering the output side green. This is a verified RungProof
behavior change, not yet a parity pass: compare the same false/true timer and
counter states against the installed TIA version before closing monitor gates.

The current shared canvas also retains the last identity-matched value for a
JMP-skipped instruction while keeping its current flow unknown. Native
`TIA_EARLIER_CYCLE_VALUE_VERIFY PASS` checks a full-saturation current value,
the deterministic half-saturation earlier-cycle value, gray/unknown skipped
flow, and cache retirement at a load boundary. The inspected 100% capture
`.tools/tia-flow-earlier-cycle-v1.png` shows three retained `FALSE` values in
the skipped network while every conductor and instruction symbol remains gray.
This is local evidence for the cross-cutting state; per-instruction-family and
same-state installed-TIA comparisons remain open.

### Bit-logic source audit added 2026-10-13

The current source's NO/NC evaluation and assignment/S/R write behavior were
checked against Siemens STEP 7 LAD references. This is source-level semantic
evidence only; all state cells above remain OPEN until running editor captures
are compared to the same CPU/version and state in TIA.

- NO/NC contacts evaluate BOOL operands and invert NC as expected; capture true
  and false states in series and parallel, checking the contact bars/slash,
  centered operand, and conductor endpoints.
- The S7-1200/S7-1500 `--|P|--` and `--|N|--` instructions read the signal
  operand above and a unique edge-memory BOOL below; the memory bit records the
  prior signal state. Address reuse corrupts edge evaluation. Siemens allows
  M-bit or DB/static storage. See the official [positive-edge P contact,
  STEP 7 V20](https://docs.tia.siemens.cloud/r/en-us/v20/lad-s7-1200-s7-1500/bit-logic-operations-s7-1200-s7-1500/p-scan-operand-for-positive-signal-edge-s7-1200-s7-1500?contentId=fNuTI~Efk0z~onnwDEYkIw)
  and [negative-edge N contact, STEP 7 V20](https://docs.tia.siemens.cloud/r/en-us/v20/lad-s7-1200-s7-1500/bit-logic-operations-s7-1200-s7-1500/n-set-operand-on-negative-signal-edge-s7-1200-s7-1500).
- The current implementation carries an optional memory operand through the
  runtime IR, recursive/flat editor models, serializers, compiler,
  instance/call-scope transforms, tag rename/references, copy/paste,
  observations, property editor, and renderer. New contacts allocate a unique
  writable BOOL. The compiler rejects repeated symbols, duplicate explicit
  absolute addresses (including `%` aliases), wrong memory areas, and bit
  addresses outside M-bit or DBX-bit form. Blank/symbolic addresses and
  instance-local absolute layout cannot be confirmed by this offline compiler;
  this is a documented limitation, not proof that storage is valid on a CPU.
  Legacy P/N instructions with no operand still load through the old
  instruction-ID state path, so automatic migration would change behavior and
  remains intentionally unresolved.
