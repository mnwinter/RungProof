Existing expected-behavior-matrix.md was used for context; current scene JSON/help and explicit saved-project files are the detailed sources below. A declaration is not proof that a face is rendered or responds.

## Common control families

- **S — sequence-start:** thirteen legacy sequence scenes expose START/RAISE/OPEN actions. Main.cs:5257–5283 requires controllerStartBinding and a loaded BOOL Input with that exact Binding. It does not infer a PC input from a PLC output or directly execute the legacy sequence in normal loaded-controller operation. Seven scenes/nine START actions have no declared binding; those are static contract blockers pending an actual UI attempt, not runtime failures.
- **B — raw inputs:** toggle/togglePoint are maintained input changes; pulse is an accepted event, not a maintained toggle. Check the PC input image and the loaded PLC output separately. A physical pushbutton style does not by itself establish momentary semantics.
- **C/P — counters, timing, state:** accepted edges/scans and actual plant feedback own expected transitions. Idle/held/repeated actions, Stop/reset and fresh-start paths need separate checks. Wall-clock waits do not prove an exact accepted-scan boundary.
- **A — arithmetic:** UI cycle actions provide explicit numeric values. Load the opt-in reference through Project>Open; validity flags and result values must be checked independently.
- **T — authored typed/handshake:** three code-authored starters exist (10.1,10.2,10.4). Their presence in the editor is not Verify+Load or a running program.
- **E — environment:** LOAD/ENTER/EXIT/QUEUE modify simulated material/fixture conditions and yield PC feedback; they are not permission to write PLC commands. Preserve load eligibility and reset constraints.

## Ownership and playback rules

- Main.cs:5210–5295 is the normal UI action boundary. With no loaded controller, type=start/run and PLC-owned point actions are blocked. With a loaded controller, type=stop/reset invokes app StopActiveController/ResetActiveController; a modern pulse machine_stop/reset input is a different path.
- A sequence controllerStartBinding may be a supported manual controller binding such as operator.start, even when no SceneIO point of that name exists. The project must explicitly declare a BOOL Input bound to it. It must not be synthesized as a PLC output or assumed from a button label.
- SceneLadderProject.Create creates SceneIO tags/watch entries without solution networks. AuthoredLessonLadderPrograms.TryCreate supplies only10.1/10.2/10.4; the five demos use their own authored path. Other explicit programs/examples files are opt-in, not auto-loaded solutions. Saved file existence/SourceSceneId was checked by JSON reading only; compatibility and behavior remain to be proved through UI loading.
- Sequence simulation JSON still contains legacy set/rules/edgeRules/sequences. Their presence is not a valid PLC solution oracle and does not prove normal UI transport. In particular, do not bypass missing controllerStartBinding by running a backend sequence action.
- Each physical-control cell lists declared action labels, types, targets/ownership, and configured equipment faces where present. “Action only” means no direct matching equipment config/point binding was found in that JSON; it does not prove a missing runtime-generated cabinet control.
