# Remaining loaded-controller plant adapter candidates

Read-only source assessment, 2026-10-22. No runtime PASS claims. Operator bindings provide requests; they do not supply a PLC sequence. Existing v2 fixtures remain limited by their documented contracts.

## Already implemented in current working source

- Lab2.11: `InboundScanPlantModel` + `SceneSimulationRuntime.InboundScan.cs`: PLC conveyor command moves supported tote, actual geometry-derived scanner beam, stopped barcode dwell, PC beam/scan feedback. V3 learner ladder owns feed/scan/clearance decision; six-second exit allowance is a QA parameter.
- Lab2.12: `BidirectionalLiftPlantModel` + `SceneSimulationRuntime.AssemblyLift.cs`: mutually exclusive PLC up/down commands advance bounded lift position; PC endpoint switches and SIM position come from model; fixture follows actual lift. Verify native behavior separately.
- Other five: no dedicated opt-in adapter found in current `SceneSimulationRuntime.*`. Existing `simulation.type=sequence` recipes and their PC feedback setters belong to standalone reference playback. `PositionFeedback.cs` explicitly skips reference feedback under `UsesExternalClock`.

## Common acceptance boundary

Use the existing controller scan clock, reset model from authored geometry, freeze native autonomous adapters in controller mode, preserve PC/PLC/SIM ownership, and derive sensors from actual model position/contents. Stop must remove commands and freeze plant, Reset must reproject real initial feedback, and contradictory directional commands must not move. Pure-model tests establish bounded physics; actual native clicks plus visible geometry/Signals remain required for acceptance. This note proposes candidates, not application defects beyond native-confirmed gaps.
