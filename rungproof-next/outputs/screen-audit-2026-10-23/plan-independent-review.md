## Avoid Main/Shell integration conflicts

Use **one integration owner for Main.cs, SimulatorShell.cs and their status/framing call flow**. Camera and footer diagnosis can be read-only parallel; simultaneous overlapping edits are inefficient. The plant owner can own ParcelTransferPlantModel/runtime adapter and focused geometry tests, with reserved/serialized integration at Main reset boundaries. Keep the documentation lane independent. One separate native reviewer should accept each supplied case after the integration build; the developer's unit verifier is supplemental evidence, not a substitute for clicked behavior.

Do not create three isolated source variants and repeatedly test stale binaries. Integrate a coherent narrow group, record build/DLL identity, perform its focused acceptance, then checkpoint. Preserve the immutable migration baseline and prior failures.

## Challenges to tempting shortcuts

- Restoring parcel home yaw before measuring a world AABB is plausible for the current identity-parent scene, not a general transform-proof geometry design. [Independent challenge](independent-challenge.md) shows parent rotation/scale and origin limitations. Require actual composed-scene regression before broadening a helper or claiming all delivered equipment is fixed.
- Do not combine center-sensor/admission redesign with the narrow reset fix unless the integrated failing regression proves the narrow fix insufficient. Native firstV7 batch and phase-qualified Stop/recovery already succeed; historical controller stalls alone do not justify rewriting the sorter.
- Clearing the footer unconditionally on Run can hide invalid current drafts. Framing all environment geometry can put the camera outside an opaque envelope again. Both need exact current-state/visible-route acceptance, not broad shared-code assumptions.
- A documentation ambiguity is a real issue but not evidence of faulty PLC execution. Radar candidate certainty differs from the three native functional/presentation failures. Gallery incompleteness is epistemic, not an automatic new application defect.

This order is an independent proposal for the authoritative global plan. Close each issue only against its stated evidence, preserve unresolved observation limits, and retain per-mode/local-simulator boundaries rather than announcing full-app acceptance.
