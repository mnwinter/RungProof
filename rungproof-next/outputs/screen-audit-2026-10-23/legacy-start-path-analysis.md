## Genuine candidates and smallest coherent future changes

1. **Declared route versus exposed route:** each scene declares start/stop/reset, but only its start action is mapped to3D equipment. The old action container is explicitly hidden (`SimulatorShell.cs:4433–4434`). Declared action tables in Help do not prove clickable controls. If invoked through the dispatcher, type stop/reset already calls the same App lifecycle methods (`Main.cs:5256–5257`), not an independent PLC machine-stop input. Smallest repair is to document the actual App Playback Stop/Reset route and mark reference-only action names accordingly. Adding physical buttons is optional product work, not a prerequisite for inventing five missing button tests. The queue correctly retains this as a route/documentation question (`native-test-queue.md:224–229`).

2. **Robot restart wording needs mode/action precision:** scene832 says Reset is required before restarting a stopped reference, yet native App Run resumes the retained accepted task. Source explains the difference: local AppStop commits a stopped controller snapshot without calling StopSimulation (`Main.cs:1666–1692`); a new StartSequence checks ReferenceNeedsReset (`runtime857–864`). Clarify AppStop→Run continuation versus starting a new reference. Preserve the reset guard that prevents teleporting held/deposited loads; do not remove it to reconcile wording.

3. **Tote stale hints are demonstrably outdated:** scene619/621 still say cap application is not implemented/connected, while the current cap adapter and reviewed actual cap_appliedTrue contradict that. Correct those statements and distinguish controller process from standalone geometry preview. This is justified documentation cleanup without changing actuator behavior.

4. **2.21/2.22 completion/status needs a declared mode contract:** their dedicated controller branches return before JSON sequence completion presets (`tote scene585`; dual scene410). Source and native false/amber endpoints agree. The existing verification dictionaries also lack an explicit current-controller/reference distinction; they must not be credited as proof of arbitrary loaded LAD. Lowest-impact repair is to qualify legacy SIM readouts/reference expectations. If product instead requires a controller-mode completion readout, define a passive actual-history predicate first: initial all-home/all-Off is **not** a completed dual-spindle cycle; tote exit alone is **not** a passing finish. Do not set complete merely from stopped commands, change SIM to PLC ownership silently, or start legacy sequencing alongside LAD. Such a behavioral change needs its own agreed scope and regression.
