## Sensor contract detail: avoid changing three meanings at once

The current help defines primary_table_loaded as a25mm-radius CENTER sensor; primary_table_clear means no carton occupies the deck. The physical center signal should be a function of the carton reference position, not its private route label. A deck-occupancy signal should instead use the appropriate whole-footprint/deck intersection. An index-eligible signal additionally depends on support/position/actuator state. These can legitimately differ and must not share an ambiguous Boolean definition.

For current authored geometry, reference X/Z is the controlled rigid body root. Actual delivered accessory offsets and local origin should be checked before claiming it is a material centroid. Do not substitute a rotated world-AABB center or whole-footprint intersection and retain the old25mm description. A small helper with explicit semantics used consistently across feedback and mechanics is preferable to three subtly different predicates.

A shared centered predicate alone also does not decide when outbound route ownership becomes irreversible. Two coherent choices exist: route remains provisional while the load is physically reorientable at center, or route is committed only on actual departure from that envelope. Either choice must handle p.X/p.Z/Angle/Outbound consistently when a stopped centered load is indexed. Neither should choose a route from ClassFor or issue later commands on LAD's behalf.

## Geometry mismatch versus classification

The previous pure harness linked real model/runtime source, but supplied nominal sizes and omitted Godot support. Native adapter instead obtains dimensions from merged delivered world AABBs and beam thresholds from imported mesh global centers minus the first carton's bounds bottom (ParcelTransfer.cs:50-62). SceneComposer.cs:268-295 moves actual beam meshes from their authored heights to configured heights. Catalog bounds, static delivered bounds, importer transforms, current owner rotation and child pose can therefore affect adapter parameters without changing the scene JSON.

Static glTF inspection narrows two differences: actual delivered carton height is about3.47percent greater than its catalog height after scaling, and its depth is slightly below the nominal config. For this scene the height bands still clearly separate the three declared sizes; a retainedY-axis yaw alone does not change height. This report does not infer an actual class reversal. Root's Watch/signal evidence is authoritative for the current controller; exact private beam/AABB numbers remain unqueried native state.

Before choosing a general geometry repair, decide where canonical physical dimensions live: immutable delivered owner-local geometry, an explicit validated collision envelope, or scene configuration. Currently the adapter mixes a world-AABB measurement with a local rigid-body pose model. Any selected authority should be converted once into a consistent frame and paired with visible geometry; do not mix a previous-frame broad-phase box with newly reset local orientation.
